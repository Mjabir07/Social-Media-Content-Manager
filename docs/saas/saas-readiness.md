# SaaS Readiness

AZMIN OS is built for internal use first. These foundations preserve the option to
sell it later without imposing unnecessary complexity now.

## Build early

- Tenant-aware data model and server-enforced isolation
- Roles and permissions
- Tenant branding, timezone and currency
- Feature flags and plan entitlements
- Audit and usage events
- Data export capability
- Safe suspension/deletion states
- Provider-adapter architecture

## Build only when commercialization begins

- Public tenant signup and trial conversion
- Automated SaaS billing, taxes and coupons
- Multiple commercial plans
- Customer support portal
- Advanced platform administration
- Formal onboarding and product analytics

## Possible plans

| Plan | Target user |
| --- | --- |
| Solo | Freelancer managing personal operations |
| Agency | Multiple clients, services and approvals |
| Business | One company managing internal operations |
| Partner | Lead attribution and commission workflows |
| Enterprise | Custom hosting, controls and integrations |

Plans use entitlements rather than separate codebases.

## SaaS release gates

- Independent security review
- Tenant-isolation penetration tests
- Backup and restoration drill
- Privacy, terms and data-processing documents
- Subscription and entitlement accuracy tests
- Usage/cost protection and abuse limits
- Customer data export/deletion tests
- Support-access audit controls
- Monitoring and incident-response readiness
